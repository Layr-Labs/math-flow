These were unpublished, publication-forbidden branch experiments. The

## Compatibility diagnostic

Run 33474307250 stopped at the first route request because the provider rejected
`uniqueItems` in the strict structured-output schema. It made one rejected HTTP
request, returned no model response or usage, and never reached a semantic
stage. The provider-visible schema now omits unsupported strict-schema keywords;
trusted route binding still enforces unique IDs and queries. A recursive test
checks the supported strict-schema subset.

## Governed paid holdout

Run 33474475581 then exercised the actual V10 route, route-refine, and organize
stages. It made nine provider calls. Eight calls in seed 1729 returned complete
usage telemetry; their reported totals were:

- 123,333 prompt tokens;
- 24,718 completion tokens, including 17,377 reasoning tokens;
- 148,051 total tokens; and
- $0.5386691 OpenRouter-reported cost.

Seed 2718 received one OpenRouter 502 response with `Provider returned an empty
response`, no model identity, and no usage or cost telemetry. The experiment
therefore treated the possible cost as unknown and blocked every subsequent
call. The three journal entries represent the governed stage exhausting its
internal attempt loop against the same blocked call; only one provider request
was made. The reported total above does not include any unreported charge for
that response.

After this audit, the governed adapter gained an explicit terminal transport
outcome. Missing telemetry, an uncertain transport result, or a hard experiment
budget now records one rejected attempt and exits with `further retries were
suppressed`; it cannot manufacture two more logical retry entries or make
another provider call. Ordinary structured-output and semantic validation
failures retain the bounded diagnostic retry path.

Seed 1729 completed the sequential K2 then K3 chain. K2's first route response
used the entire 4,000-token completion allowance, mostly for reasoning, and was
length-truncated. The governed diagnostic retry was accepted. K3's first route
named an unknown result ID, and the bound-route validator rejected it; the next
response corrected the ID. Both refine and organize stages were accepted on
their first attempts.

## Precommitted relational result

The completed seed failed three hard assertions:

| Assertion | Expected | Observed |
| --- | --- | --- |
| K2 adds one root-child UV program | 1 | 0 |
| K2 creates one program operation | 1 | 0 |
| K2 refreshes only root among existing programs | 1 content operation | 3 content operations |

V10 created one reusable UV intermediate result but placed it inside the
existing K1 `program-channel-specific-converse-refinement` branch, then refreshed
that branch, its code-induced parent, and root. Its rationale said no new program
was warranted because the theorem changed that existing channel-specific
package. K3 correctly recognized the overlapping later submission, reused the
same result and program topology, retained both submissions' claim/judgment/
source provenance, and performed no topology operation.

The first two assertions are two manifestations of the same real placement
defect. The third is useful evidence in this sample—the two extra rewrites move
UV-specific state into K1—but raw content-operation count is too rigid as a
general oracle. A correctly root-owned new package could also have a justified
cross-effect on some existing program. Future scoring should assert root
ownership, conditional-parent semantics, dependency-only K1 use, and preserved
K1 objectives/residuals unless an explicit related-impact rationale is present,
rather than always requiring exactly one content operation.

The result-level two-way split remained advisory. As in the earlier V9 holdout,
V10 represented the general additivity theorem, receiver-skew bridge, and BSSC
specialization as one dependency-ordered reusable result. This remains a
semantic retrieval policy question rather than a program-accounting failure.
The aggregate does blur dependency scope: its K1 dependency is needed only for
the BSSC specialization, not the general finite-DMBC theorem. That can be
addressed either with two reusable results or a future claim/subresult-level
dependency annotation without creating two accounting programs.

The program placement is a real regression relative to both the frozen gold and
the earlier generalized V9 candidate. The K2 work has its own activation and
stopping condition; its mathematical reliance on a K1 result does not make its
work conditional on pursuit of the K1 code-induced branch. The accepted
submission even states that the UV program lies outside the registered K1
scope. Nesting it under K1 would make downstream work-incidence and remaining-
work accounting depend on the wrong parent policy.

Raw submission evidence was absent from both routing stages, as intended. The
K2 route context was 7,623 bytes; its exact discovery/author packet was about

context risks and that the organize stage can be evidence-dominated.

## Protocol correction

The V10 prompt retained the headline intervention test but had compressed away
several operational clauses that made the V9 candidate reliable. The corrected
inactive spec now tells both routing stages and the author that:

1. program boundaries use an author-blind work-policy intervention test;
2. topical relation is insufficient when activation or stopping conditions are
   independent;
3. a child is nested only when pursuing it is conditional on pursuing its
   accounting parent;
4. mathematical/evidentiary dependency never establishes accounting ancestry;
5. root is correct when no narrower genuine shared activation gate exists; and
6. topology rationale must identify shared and independent activation events;
   and
7. the split test is applied to the same-world no-access work package even when
   the current contribution completes it and leaves zero with-access work.

The route completion allowance was also raised from 4,000 to 6,000 tokens.
The accepted retry itself used 3,966 completion tokens, so the original limit
left essentially no headroom for a high-reasoning route decision and its small
structured answer. The refine limit remains 4,000 because both accepted refine
responses used at most 1,276 tokens.

This is a prompt correction, not a mechanical topology guard. The reducer still
permits semantically justified alternatives and enforces only structural,
identity, scope, and hidden-state invariants.

## Decision

The local/fractal context architecture passed its mechanical and information-
flow checks, and the successful K3 reuse is encouraging. The paid sample does
not support activation: its completed seed failed the central program-accounting
holdout, while the other seed ended in a provider response with unknown cost.
The unchanged candidate must not be retried. The revised prompt should first be
exercised by the provider-free regression ladder and then, if those checks stay
clean, by one explicitly bounded replacement holdout.
