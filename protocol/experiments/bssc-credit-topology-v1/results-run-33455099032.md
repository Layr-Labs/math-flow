## K1 accounting topology

The baseline undersplit both seeds: one combined program and one combined
intermediate result represented finite-block code-induced structure and the
entropy/copy obstruction. It therefore failed the desired credit resolution in
2 of 2 semantic samples.

The accounting rubric produced the intended semantic topology in both raw
responses:

```text
root
└── narrow code-induced converse portfolio
    ├── structure-preserving single-letterization / dependence balance
    └── BSSC-specific posterior or channel-consistency refinement
```

Each response also produced two separately linked intermediate results and kept
their mathematical dependency distinct from accounting ancestry. Both were
reducer-rejected for the control errors above, so the result is 2/2 semantic
topology success and 0/2 executable first-attempt success.

The worked-example variant separated the two work packages in both seeds. One
seed created a parent and two leaves; the other used two root siblings and
claimed root was the shared gate. The created parent was named broadly as
`BSSC converse strengthening`, and its rejected K2 continuation then placed the
independent UV scalar route beneath it. Relative to the frozen gold, this is an
overbroad grouping parent rather than the narrow K1 portfolio.

Therefore the worked example did not improve semantic topology over the concise
rubric. It may encourage generic portfolio scaffolding. The rubric itself is the
stronger signal, provided the narrowest-shared-gate rule is made explicit.

## Validity-fidelity regression

The authoritative K1 scope qualification says exact binary-posterior and other
channel-specific consistency constraints **may exclude** the finite witness.
The accepted baseline preserves that modality. All four accounting-guided K1
responses strengthen or muddy it:

- accounting: `can exclude` or `exclude`;
- worked example: `can exclude` or `exclude or may exclude`.

This is a separate semantic defect. A topology improvement is not an overall
protocol pass when future-work descriptions convert a possible research route
into an established capability. The fix should remain semantic and general:
validity-controlled modality must be preserved everywhere, including program
objectives, summaries, residual work, rationales, and result qualifications.
For example, accepted `may` must not become `can`, `does`, or an unqualified
imperative premise.

## Decision and next experiment

The evidence supports refining the accounting prompt. It does not support a
structural `program`/`thread` role or schema constraint yet: the current program
tree expressed the desired hierarchy in both accounting-rubric samples.

Recommended prompt refinements:

1. Require the narrowest shared activation gate; root is not an adequate
   substitute when siblings share a materially narrower objective, and generic
   wrappers must not absorb independently activated future programs.
2. Require validity-controlled epistemic modality in every surface, with a
   domain-neutral example that `may` cannot become `can` or `does`.
3. Clarify the operation contract: each entity appears in exactly one operation
   array; ancestry alone does not make a parent a result link; existing-result
   updates refresh the owning program and every ancestor through root.

A targeted follow-up should compare the concise rubric with the refined rubric
over three or four independently seeded K1 runs using normal governed retries,
while retaining first-attempt journals. K2 and K3 should then use fixed accepted
K1 bases or independent fixtures so a mechanical K1 failure does not censor the
later semantic cases. Score topology, modality, and control validity separately.
