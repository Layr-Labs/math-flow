## Retry and contract defect

The first provider response was complete but marked one newly created program
`completed`. The research-builder reducer correctly rejected it because new
entities must be active. The V2 response schema had nevertheless allowed
`active`, `blocked`, or `completed`, and its prompt said to use active
unless a package was fully closed.

The governed retry returned all created programs as active and was accepted.
The run therefore made two provider calls rather than one.

The additive V3 successor removes this avoidable mismatch mechanically:
created-program status is the constant `active`, and the reducer also requires
every fixed newly created intermediate result to be active. Completion is
represented by the result, residual-work description, and W+ primitives—not by
creating a completed entity.
