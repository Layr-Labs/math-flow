# Results: run 33457244165

GitHub Actions run: <https://github.com/Layr-Labs/math-flow/actions/runs/33457244165>

This was an unpublished, non-canonical fixed-K1 prompt comparison. Six
independent Builder V9 evaluations started from the same empty state and used
the same accepted K1 claim and repository evidence. The production job was
skipped and no projection state was published.

## Usage and governed retry behavior

- 6 of 6 evaluations reached an accepted transition.
- 9 of 18 maximum OpenRouter calls were made.
- 359,270 prompt tokens, 61,477 completion tokens, and 420,747 total tokens.
- 28,900 of the completion tokens were reported as reasoning tokens.
- OpenRouter-reported cost: $0.7796869.

By variant:

| Variant | Accepted | First-attempt accepted | Calls | Tokens | Cost |
| --- | ---: | ---: | ---: | ---: | ---: |
| Accounting rubric | 3 / 3 | 1 / 3 | 6 | 283,374 | $0.4913568 |
| Refined accounting rubric | 3 / 3 | 3 / 3 | 3 | 137,373 | $0.2883301 |

The refined prompt was 330 prompt tokens longer on an initial request. Its
lower aggregate cost and token use came from avoiding retries, not from being a
shorter prompt. These are three fixed-case samples, not an estimate of general
provider cost or judge variance. Cache state also differed across calls.

The concise accounting rubric incurred three reducer rejections:

- seed 1729 repeated every new entity in both operation arrays; retry 2 passed;
- seed 2718 repeated every new entity in both operation arrays on attempt 1,
  then used a result placement across comparable ancestor/descendant programs
  on attempt 2; retry 3 passed; and
- seed 3141 passed on its first attempt.

There were no transport, length, empty-response, or JSON failures. All three
refined responses obeyed the operation contract on their first attempt: root
was the only content update, every new entity appeared once as a topology
create, grouping parents had no result links, and contribution direct-program
sets equalled the union of leaf result links.

The rejected accounting attempts also used the base-state digest where the
accepted validity judgment ID belonged. Reducer feedback eventually led the
accepted responses to the correct judgment binding, but the initially reported
reducer error was encountered first. This is another reason to inspect complete
attempts rather than treating the first validator message as an exhaustive
semantic audit.

## Precommitted scoring

The frozen gold required a narrow shared parent, two independently updateable
leaf programs, two separately reusable intermediate results, possibility-level
modality for channel-specific exclusion, and a mechanically valid transition.

| Final accepted property | Accounting | Refined accounting |
| --- | ---: | ---: |
| Narrow parent plus two leaf programs | 1 / 3 | 3 / 3 |
| Two separately placed intermediate results | 1 / 3 | 3 / 3 |
| Controlled `may exclude` modality on every surface | 0 / 3 | 2 / 3 |
| Gold operation contract in final output | 1 / 3 | 3 / 3 |
| Reducer acceptance on first attempt | 1 / 3 | 3 / 3 |
| Complete gold pass | 0 / 3 | 2 / 3 |

Thus the refined prompt reproduced the intended accounting hierarchy and result
partition in all three samples. The concise rubric remained seed-sensitive:
one accepted output collapsed both work packages and both epistemic components
into a single program and result. Another created two leaves beneath the
overbroad `BSSC converse development` umbrella and represented both epistemic
components as one result linked across the siblings. Only seed 1729 reproduced
the complete narrow-parent organization.

Reducer acceptance and the stricter precommitted operation contract are not the
same measurement. Accounting seed 3141 was reducer-accepted on its first
attempt, but created its new program and result through content operations.
Accounting seed 2718's final response similarly created its new combined result
through a content operation. Only accounting seed 1729's final response used
topology creates for every new entity. All three refined responses did so.
The present reducer therefore permits a transition form that this experiment's
gold contract rejects; the prompt improvement avoided the mismatch, but did not
change validator behavior.

All three refined parents were materially narrower than root and left unrelated
future converse routes outside their scope:

- `Code-structured converse development`;
- `Code-induced dependence-balance converse development`; and
- `Dependence-balanced converse refinement`.

Their wording differs, but each represents the shared activation event of
turning code-induced dependence-balance structure plus valid BSSC-specific
constraints into a stronger converse. Each parent retains no direct result;
the finite-block structural result belongs to the support-reduction leaf, and
the scoped entropy/copy obstruction belongs to the channel-specific leaf.

## Qualification fidelity

The refined modality instruction improved but did not solve qualification
fidelity. Seeds 1729 and 2718 preserved the accepted conclusion that exact
binary-posterior or other channel-specific constraints **may exclude** the
witness. Seed 3141 instead stated:

> Exact binary-posterior consistency excludes this witness.

Under the precommitted rule this is an unsupported strengthening, even if a
judge can motivate it from the witness description. Accepted validity controls
what the knowledge builder may assert; the builder should frame the residual as
investigating whether such consistency excludes the witness.

The concise accounting outputs were worse. Final seed 1729 preserved
`may exclude` in the result qualification, but its program residual requested
constraints "that exclude" the witness, so it fails the every-surface rule.
Final seeds 2718 and 3141 used `can exclude`, and seed 2718 also stated in a
program summary that exact binary-posterior consistency excludes the witness.
Retries therefore did not reliably preserve or repair modality.

This is a semantic reliability issue. The experiment does not support adding a
deterministic verb-matching guard, and this report does not propose one.

## What changed the result

The follow-up added three prompt-level controls to the accounting rubric:

1. choose the narrowest genuine shared activation gate, rejecting both root as
   an under-nested substitute and generic converse umbrellas as overbroad;
2. keep grouping parents free of result membership, attach results to the leaf
   work packages they directly update, and preserve accepted epistemic modality
   on every surface; and
3. state the operation-array, direct-program-union, and ancestor-refresh
   contracts explicitly.

The first two structural controls yielded the intended three-program/two-result
organization in 3 of 3 samples. The operation contract converted a 1-of-3
first-attempt acceptance rate into 3 of 3. The modality control improved
strict every-surface fidelity from 0 of 3 to 2 of 3 but remains incomplete.

## Causal limits and smallest next revision

The comparison holds subject, state, model, seeds, evidence, and accepted
validity fixed, so the prompt bundle is the most plausible cause of the observed
difference. It does not isolate which sentence caused which gain: narrow-parent,
result-placement, modality, and operation instructions changed together. It is
also a K1 in-sample test whose language directly addresses failures observed in
the preceding experiment.

The smallest generalizing revision for the next candidate is:

- state that accepted scope qualifications limit every stronger-looking
  declared statement, and that when assessment surfaces differ in strength the
  weaker intersection controls every output;
- replace the K1-shaped leaf-only linking instruction with a general rule to
  link a result only to the narrowest programs whose own remaining work it
  directly changes, allowing a parent link only for genuine parent-level
  integration or coordination work and never for ancestry alone; and
- frame the split test author-blindly: split when plausible future evidence
  could change the continue/stop decision for one package without changing the
  other, not to maximize attributable credit for the current submission.

This keeps topology informed by downstream accounting without asking the
knowledge builder to estimate probabilities, hours, deltas, or awards.

## Decision

The refined rubric is a clear improvement and is the better basis for the next
builder version. This experiment still does not justify a structural
`program`/`thread` schema tag: the existing program tree represented the desired
credit-accounting topology in all three refined samples.

Before activating it as a production lane, the next regression should hold one
or more accepted K1 bases fixed and test later submissions, with two independent
seeds per transition as a small gate. It should check that:

- an independent route becomes a root sibling rather than being absorbed by
  the new parent;
- dependent mathematical evidence remains a result dependency rather than
  false accounting ancestry;
- later evidence for an existing package reuses its program and result IDs; and
- controlled epistemic modality survives updates and synthesis at every
  ancestor.

That continuation test is needed to distinguish a prompt that draws the right
initial picture from one that maintains a useful accounting state over time.
