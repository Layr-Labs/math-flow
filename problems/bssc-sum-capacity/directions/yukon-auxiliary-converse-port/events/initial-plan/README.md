# Yukon auxiliary-converse port and replay

## Objective and bounded scope

Port, independently replay, and preserve the remaining accepted auxiliary-receiver converse work from the local Yukon BSSC research record into canonical Math Flow as a sequence of coherent atomic contributions. The source snapshot is the repository `/Users/robert/eig/autoresearch/bssc/yukon-bssc-challenge`, branch `local-yukon/canonical`, commit `1af4e641fcfd4c76ec382c4e7cd5bed32af15e9c` (the branch is named with a slash even though it has sometimes been described informally as `local-yukon-canonical`). All source reads and hash comparisons will be against that immutable commit, not the source checkout's dirty working tree.

The bounded inventory is the previously audited set of 31 accepted Yukon artifacts belonging to the Gohari–Liu–Nair auxiliary-receiver program and its simplified equation-(16) subprogram at that source snapshot. The port begins with the exact 30-row/full-row structure, rank-eight skew-invariant quotient, sparse lift, and reflected invariant-cone exclusions. It then ports the globally certified simplified equation-(16) functional, including the arbitrary-finite-alphabet reduction and its continuous interval certificates. The remaining accepted inventory will be divided into later atomic contributions by mathematical claim and verification boundary.

This direction does not include the separate Yukon programs on direct code-induced dependence geometry, UV product additivity, or multiletter Marton achievability.

Those claims and files will be reused by exact transaction reference rather than re-submitted. The new rank-eight stage is broader than the already canonical identity for one frontier functional: it audits the complete 30-row `R_0=0` expansion, the 15 skew-paired tensors, the exact rank-eight quotient cone, a nonnegative sparse right inverse, and accepted all-weight reflected exclusions. It will not claim that skew-invariant duals are globally sufficient. The equation-(16) stage is a different, simplified functional; its lower endpoint is not a capacity lower bound, and its certified fixed-pair upper endpoint is weaker than the current full-Theorem-9 capacity upper bound.

## Staged method

1. **Inventory and provenance lock.** Enumerate the 31 accepted source artifacts at the pinned source commit; record their source submission branches/commits, judgment or knowledge provenance, files, claims, and checkers. Assign each item to an already-canonical transaction, a planned atomic port, or an explicit exclusion with a reason such as exact duplication, supersession, inapplicability, or inability to reproduce.
2. **Full-row/rank-eight structure and invariant exclusions.** Reproduce the coherent checkpoint represented by old local Math Flow commit `dc2a197371770740f0a3c1102e8fe556def0b63c` without modifying or trusting its worktree. Re-read every source file from the pinned Yukon commit, verify byte identity for copied artifacts, inspect all code before execution, and rerun the exact row/tensor/rank computations and each relevant selector or interval checker. Submit the exact full-row expansion, quotient/lift theorem, and compatible reflected invariant-exclusion claims as one atomic contribution only if their shared checker boundary remains coherent after audit; otherwise split at that boundary.
3. **Simplified equation-(16) global enclosure.** Independently replay the accepted `upper-structural` line. Verify tagged-output convexification, reflection reduction, posterior-measure potential construction, outward-rounded affine support on all of `[0,1]`, and the continuous reflected-pair majorant. Preserve the certified enclosure
   `0.3692971966457781126516 <= V_maxmin <= V_minmax <= 0.369297196647212180877`
   only if all deterministic checkers reproduce it. State explicitly that this closes the simplified equation-(16) route at that resolution but does not improve the canonical capacity frontier.
4. **Remaining accepted auxiliary-converse lines.** Continue in dependency order, grouping only claims that share a proof object and reproducibility boundary. Likely groups include the exact linear-size sampled full-row LP, frozen-surrogate floors, sharp curve links, all-weight selector exclusions, and interval-certified selected-box exclusions. Numerical searches and non-findings will be separated from exact theorems and labeled as such.
5. **Canonical follow-through.** For each contribution, validate the artifact, repository tree, full test suite, diff, and atomic PR shape; preserve authorship and immutable source provenance. After canonical merge, wait for primary judgment and formed state before relying on it for the next dependency. If the registered inventory is fully handled, submit a separate direction-completion event referencing the canonical contribution transaction IDs in ledger order.

## Expected evidence

Each port will include a precise claim and scope, original authorship, source branch/commit and source file hashes, exact canonical dependencies, deterministic reproduction commands, and known trust boundaries. Preferred evidence is exact rational row and tensor arithmetic, rank checks, symbolic identities, small selector certificates, directed/outward-rounded interval arithmetic covering the entire stated continuum, and fail-closed verification output. Any external manuscript transcription or logarithm implementation assumption will remain explicit. Copied executable code will be inspected before it is run.

## Limitations

Registration is non-exclusive and does not reserve the topic or establish correctness. Porting creates provenance and reproducibility but does not itself add mathematical authorship. The program does not promise a capacity-bound improvement, a continuum cardinality theorem, global sufficiency of reflected binary receivers or invariant duals, exact attainment of the equation-(16) infimum, global optimization of the full Theorem-9 system, matching achievability, or the exact BSSC sum-capacity. Source artifacts that cannot be independently reproduced will be reported as unresolved rather than silently promoted.

## Completion criterion

This direction is complete when every one of the 31 accepted auxiliary-receiver/equation-(16) artifacts at Yukon commit `1af4e641fcfd4c76ec382c4e7cd5bed32af15e9c` is explicitly accounted for in a checked inventory as either (a) already represented by an exact canonical transaction, (b) ported through an atomic canonical contribution whose judgment and formed provenance have been observed, or (c) excluded with a specific documented reason and evidence. All newly ported claims must have reproducible certificates or proofs, source identity records, and canonical transaction references; then a separate `complete` direction event will close the registration.
